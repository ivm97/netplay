# netplay

## Описание

Виртуальная LAN между двумя (пока что) ПК для игр.

## Архитектура

Чистый P2P по UDP, без сервера.
Опциональный STUN только сообщает хосту публичный IP:порт (пакеты игры через STUN не идут).
При строгом NAT достаточно проброса одного UDP-порта.

Игры видят общую подсеть `10.77.0.0/24`:

| Роль   | IP в игре   |
|--------|-------------|
| Хост   | `10.77.0.1` |
| Гость  | `10.77.0.2` |

Трафик между пирами шифруется (ChaCha20-Poly1305, ключ из общего пароля).

## Требования

- **Linux** или **Windows**
- Права администратора / root (нужны для создания TUN-адаптера)
- На Windows рядом с `netplay.exe` должна быть `wintun.dll` — при отсутствии программа скачает её сама с wintun.net

## Сборка

```bash
cargo build --release
```

Бинарник:

- Linux: `target/release/netplay`
- Windows: `target/release/netplay.exe`

## Как пользоваться

Нужны **два ПК**, общий **пароль** (минимум 4 символа) и способ передать гостю адрес хоста вида `IP:порт`.

### Вариант 1 — мастер (проще всего)

На обоих ПК запустите без аргументов (от администратора):

```bash
netplay
```

1. **Хост** выбирает `[1]`, вводит пароль (порт по умолчанию `51820`).
2. Программа через STUN покажет публичный адрес — **скопируйте другу адрес и пароль**.
3. **Гость** выбирает `[2]`, вводит адрес и пароль от хоста.
4. После «партнёр подключён» оба открывают игру в режиме LAN и ищут хост по `10.77.0.1`.

Пункт `[3] Reconnect` повторяет последнее успешное подключение.

### Вариант 2 — командная строка

**Хост** (создаёт комнату, ждёт гостя):

```bash
netplay host -p "ваш_пароль"
```

Опции:

| Флаг | Значение по умолчанию | Зачем |
|------|------------------------|--------|
| `--port` | `51820` | UDP-порт прослушивания |
| `--bind` | `0.0.0.0` | На каком интерфейсе слушать |
| `--no-stun` | выкл. | Не узнавать публичный IP (скажите гостю адрес вручную) |
| `--no-save` | выкл. | Не сохранять профиль для `reconnect` |

**Гость** (подключается к хосту):

```bash
netplay join --peer 203.0.113.10:51820 -p "ваш_пароль"
```

| Флаг | Значение по умолчанию | Зачем |
|------|------------------------|--------|
| `--peer` | обязателен | Адрес хоста `IP:порт` |
| `-p` / `--password` | обязателен | Тот же пароль, что у хоста |
| `--port` | `0` | Локальный UDP-порт (`0` = любой свободный) |
| `--no-save` | выкл. | Не сохранять профиль |

**Повтор прошлого раза:**

```bash
netplay reconnect
```

Профиль пишется в каталог конфигов ОС (`…/netplay/profile.json`) либо по пути из переменной `NETPLAY_PROFILE`.

## Типичный сценарий

1. Хост: `netplay host -p secret42`
2. В консоли хоста появляется блок «что сообщить другу» (адрес + пароль + готовая команда `join`).
3. Гость: вставляет команду или вводит данные в мастере.
4. Оба видят сообщение о подключении → запускают игру → хост = `10.77.0.1`, гость = `10.77.0.2`.
5. В следующий раз: `netplay reconnect` на обоих ПК (хост снова должен быть онлайн первым).

## Если не подключается

1. **Пароль** одинаковый, адрес гостю — именно тот, что показал хост (с портом).
2. На **роутере хоста** пробросьте **UDP** порт (по умолчанию `51820`) на ПК хоста.
3. Фаервол хоста должен пропускать входящий UDP на этот порт.
4. Хост и гость должны запускать программу **до** (или параллельно с) игрой и не закрывать окно, пока играют.
5. Логи подробнее: `RUST_LOG=debug netplay host -p …`

## Справка по CLI

```bash
netplay --help
netplay host --help
netplay join --help
```
